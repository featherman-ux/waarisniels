# Let op wat dit bestand wel en niet is: een verzoek, geen slot. Nette bots
# houden zich eraan, de rest niet. Wil je iets echt tegenhouden, dan moet dat bij
# Cloudflare (AI Crawl Control / WAF) — zie docs/cloudflare-setup.md §8.
#
# Zonder dit bestand serveert Cloudflare zijn eigen content-signals-robots.txt,
# en die verwijst nergens naar de sitemap. Deze wint.
#
# TWEE VALKUILEN bij het bewerken van dit bestand:
#
# 1. Een LEGE REGEL sluit een groep af, een commentaarregel niet. Zet dus nooit
#    een lege regel tussen een User-agent en zijn regels: alles daaronder hoort
#    dan bij niemand meer en wordt genegeerd.
# 2. Zet Disallow-regels VOOR Allow: /. De officiele regel (RFC 9309) is dat de
#    meest specifieke match wint, en dan zou de volgorde niet uitmaken — maar
#    lang niet elke crawler doet dat; veel simpele parsers pakken gewoon de eerste
#    regel die past. Met Allow: / bovenaan waren /beheer en /api/ voor die
#    crawlers dus alsnog toegestaan. Precies dat stond hier eerder fout.

# ----------------------------------------------------------------- iedereen
# Content-Signal is de machineleesbare versie van "indexeren mag, mijn teksten en
# foto's gebruiken om een model mee te trainen niet". In de EU geldt dat als een
# uitdrukkelijk rechtenvoorbehoud onder artikel 4 van richtlijn 2019/790 — het is
# dus niet alleen een verzoek maar ook een juridisch signaal. Zie contentsignals.org.
User-agent: *
Content-Signal: search=yes, ai-input=no, ai-train=no
# Beheer, API en dashboards horen niet in de index. Deze staan met opzet boven
# Allow: / — zie valkuil 2 hierboven.
Disallow: /beheer
Disallow: /api/
Disallow: /analytics-dashboard
Allow: /
